# 端口映射功能需求（后台 NAT 转发）

> 状态：已确认，2026-09-04 开发

## 用途

低频、面向管理员自己使用（示例：远程应用），把服务器公网端口转发到
客户 VPN 内网 IP 的某个端口，实现：

```
域名 + 端口   ==  IP + 端口   ==  vpn.example.com:20001 → 10.8.0.2:3389
```

## 与账号生命周期的关系

**不联动**。端口映射是管理员自己的运维工具，不随客户到期/暂停/吊销自动删除。
删除只能由管理员在“端口映射”页手动执行。

## 页面与操作

左侧导航新增“端口映射”：

- 列表：ID、绑定账号（可空）、目标内网 IP、公网访问地址、协议、状态、备注、创建时间、删除；
- 新增弹窗：
  - 绑定账号：可选（选择客户账号做备注关联，不强制）；
  - 目标内网 IP：必填（手动填，通常为客户当前 VPN IP，如 10.8.0.2）；
  - 公网端口：1024–65535，全局唯一；
  - 内网端口：1–65535；
  - 协议：TCP / UDP / TCP+UDP；
  - 备注。

## 后端与 NAT

- 新表 `port_mappings`（Alembic revision `b91f7c2a2f10`）；
- 管理 API `/api/port-mappings`：列表 / 新增 / 删除 / 全量重建；
- 新增/删除即调用 `/etc/openvpn/scripts/portmap.sh` 操作 iptables：
  - `nat PREROUTING`（OVPN-WM-DNAT 链）做 DNAT；
  - `filter FORWARD`（OVPN-WM-PORTFWD 链）放行到 VPN 客户的新连接；
  - 每次变更 `iptables-save` 持久化，重启不丢；
- 系统已占端口（22/53/80/443/1194/8000/8989/12346）禁止映射；
- sudoers 白名单仅放行 `portmap.sh`，面板进程无任意 root 权限；
- 全部操作进审计日志。

## 运维注意

- 目标 VPN 客户端必须在线，且内网 IP 与填写的 IP 一致；
- 若客户端重连后 IP 变化，需在页面删除后重建（或先给客户固定 IP，后续再做）；
- 防火墙重跑 `firewall.sh apply` 会保留端口映射专用链的规则；
- 故障恢复后可在面板点击“重建全部映射”或直接执行
  `portmap.sh reload <rules-file>`。
