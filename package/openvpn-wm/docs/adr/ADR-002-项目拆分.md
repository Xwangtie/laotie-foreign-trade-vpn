# ADR-002 项目拆分：openvpn-wm 与 openvpn-game

- **状态**: ✅ 已拍板
- **日期**: 2026-09-03
- **决策人**: 用户

---

## 1. 决策

把原来的单一仓库拆成**两个完全独立的项目**：

| 项目 | 内容 | 成熟度 |
|---|---|---|
| **`openvpn-wm`**（本项目） | ① 全局 ② 分流+断网不走本地 ③ 分流+断网走本地 + Web 管理端 | 🟢 现在就做，路径清晰 |
| **`openvpn-game`** | 游戏加速器：仅游戏白名单出海 + 封海外媒体 + 自研 Windows 客户端 + 扫码收款 | 🟡 长期打磨，需要很多事情 |

用户原话：
> *"方案2、openvpn-game，游戏加速，这个方案路还很长，需要很多需要打磨的事情。"*

---

## 2. 为什么要拆

| 理由 | 说明 |
|---|---|
| **成熟度差异大** | wm 的技术路径已清晰（标准 OpenVPN 分流）；game 涉及合规策略打磨、白名单长期维护、自研客户端、支付资质，周期长得多 |
| **资金隔离** | game 有扫码收款，一旦被入侵/串号损失不可逆，必须与主业务物理隔离 |
| **避免互相拖累** | 拆开后 wm 可以先上线赚钱，game 慢慢磨，互不阻塞 |
| **服务器隔离** | 各自独立 VPS，一边出问题不影响另一边 |
| **合规边界清晰** | game 是"白名单出海的游戏加速器"，wm 是"通用外贸 VPN"，定位与合规要求不同，混在一起容易互相污染 |

---

## 3. 隔离到什么程度

| 项 | 要求 |
|---|---|
| 代码 | 🔒 **零共享**。不 import / 不 source 对方任何文件 |
| git 仓库 | 各自独立 |
| 服务器 | 各自独立 VPS |
| PKI / CA | 各自独立 |
| 数据库 | 各自独立 |
| Web 面板 | 各自独立（**本项目面板不含支付**） |
| 唯一"共享" | 公开数据（国内 IP 段 / 域名列表）—— **各存一份物理副本，不做软链** |

---

## 4. 本项目（wm）明确不做的事

- ❌ 封海外媒体 / 白名单出海（那是 game 的合规策略）
- ❌ 自研 GUI 客户端（用系统/官方 OpenVPN 客户端 + 安装脚本即可）
- ❌ 扫码收款 / 订单 / 对账
- ❌ 纯客户端侧分流（旧方案A，已彻底排除）

> 如需这些能力，去 `openvpn-game` 项目。
